## 2. Problem — Why Q16 Cannot Currently Run

### Root Cause

The shadow trades and trade truth records come from **completely different eras and systems**:

| Dataset | Schema Version | Date Range | Source |
|---------|---------------|------------|--------|
| **Shadow Trades** | `trade_truth_v2` | File dated `2023-11-14` but `correlation_id` is `COR-20260704-*` | Generated by current `ShadowTradeEngine` (production Engine A) |
| **Trade Truth** | `trade_truth_v2` | File dated `2024-06-03` | Generated by legacy trade close handler (pre-correlation era) |

### Key Evidence

**Shadow Trade record:**
```json
{
  "schema_version": "trade_truth_v2",
  "source": "shadow_trade_engine",
  "correlation_id": "COR-20260704-200-EURUSD-BEEF",
  "trade_id": "T2",
  "cycle_id": "200"
}
```

**Trade Truth record:**
```json
{
  "schema_version": "trade_truth_v2",
  "trade_id": "pos_100",
  "symbol": "EURUSD_SB",
  "cycle_id": ""
}
```

### Why They Don't Match

1. **Different trade_id formats:** Shadow uses `T2`, `T3` etc. Trade Truth uses `pos_100`, `pos_1` etc.
2. **No correlation_id in Trade Truth:** The field doesn't exist in the trade_truth_v2 schema produced by the legacy system.
3. **Different time periods:** Shadow trades are from Engine A (July 2026). Trade truths are from June 2024.
4. **No overlapping trades:** There are no real trades from the Engine A era that have both shadow AND truth records.
5. **Decision Ledger has no EXECUTE records** in the available data — the system has been running in NO_TRADE/PATTERN_REJECT mode (no live trades executed during the data period).

## 6. Recommended Correlation Strategy

### For Future Data (Engine A live trading)

When Engine A executes a live trade, the system already writes:
1. **Shadow trade** with `correlation_id = COR-*`
2. **Execution result** with `correlation_id` (via `engine_execution_handler.py`)
3. **Decision ledger** with `correlation_id` (on EXECUTE path)

The **trade truth** record (written on trade close via `TradeStateManager`) needs to include the `correlation_id` propagated from the open position.

**Primary linking strategy:**
```
correlation_id (COR-YYYYMMDD-{cycle}-{SYMBOL}-{hex})
    → shadow_trades.correlation_id
    → execution_results.correlation_id
    → decision_ledger.correlation_id
    → trade_truth.correlation_id (NEEDS TO BE ADDED on trade close)
```

### For Historical Data (cannot be recovered)

The 35 existing trade truth records from June 2024 have **no correlation_id and no matching shadow trades**. They cannot be linked to any shadow prediction.

**These records are usable for:**
- Historical win rate / R-multiple statistics
- Pattern performance analysis (they have `pattern` field)
- NOT usable for shadow validation (Q16)

### Match Confidence Framework

| Match Level | Method | Confidence |
|-------------|--------|-----------|
| 100% | Exact `correlation_id` match | ✅ Definitive |
| 90% | Same `trade_id` format + symbol + direction | High |
| 75% | Same symbol + direction + timestamp within 5 minutes | Medium |
| 50% | Same symbol + direction + same trading day | Low |

**Recommendation:** Only use 100% matches for Q16. Fuzzy matching introduces noise.

## 7. Conclusion

### Why Q16 Failed

Q16 produced 0 matches because:
1. Trade truth records are from 2024 (legacy, no correlation_id)
2. Shadow trades are from 2026 (Engine A, with correlation_id)
3. There is **zero temporal overlap** between the datasets
4. The system has not executed any live trades during the Engine A era
5. Therefore no record exists in both datasets simultaneously

### What Needs to Happen for Q16 to Work

1. **The system must execute live trades** (move beyond PATTERN_REJECT/NO_TRADE)
2. **Trade truth records must include correlation_id** when writing on trade close
3. **Both shadow AND truth records** must be generated for the same decision cycle

### Is Correlation_ID Usable?

**Yes — for future data.** The correlation_id format (`COR-YYYYMMDD-{cycle}-{SYMBOL}-{hex}`) is well-designed and already propagated through:
- Shadow trades ✅
- Execution context ✅  
- Decision ledger ✅ (on EXECUTE path)

**Missing link:** Trade truth persistence needs to receive and store the `correlation_id` from the open position.

### Can Historical Data Be Recovered?

**No.** The 35 trade truth records cannot be correlated to shadow trades because:
- Different time periods
- Different identification schemes
- No shared keys

1. **Wait for live trade execution** — Q16 requires real matched data

3. **Consider shadow-only Q19** — Expected Value can be calculated from shadow trades alone (469 records available)
